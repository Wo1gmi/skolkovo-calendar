# skolkovo-calendar

Синхронизация расписания СКОЛКОВО с Google Calendar и уведомления об изменениях в Telegram.

## Проверить и обновить расписание

В GitHub откройте **Actions → Test and update schedule → Run workflow**.
Выберите ветку с изменениями и запустите проверку.
После первого слияния workflow в `main` он появится в списке Actions.

Запуск выполняет все тесты проекта, затем записывает актуальное расписание в календарь.
При изменениях отправляет обычные уведомления, а в конце — сообщение с датой,
временем и количеством добавленных, обновлённых и удалённых событий.
Даже если изменений нет, итоговое сообщение придёт.
Если тесты не проходят, календарь не обновляется.
При ошибке синхронизации уже выполненные изменения могут остаться в календаре;
запуск отмечается как неуспешный.

Для запуска используются те же секреты GitHub, что и для обычной синхронизации:
`SKOLKOVO_EMAIL`, `SKOLKOVO_PASSWORD`, `GOOGLE_SERVICE_ACCOUNT_JSON`,
`GOOGLE_CALENDAR_ID`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`.
Удаление отменённых занятий зависит от настройки `ENABLE_DELETIONS`.
Ручные цвета не сбрасываются. Задания LMS этот запуск не синхронизирует;
для них остаётся отдельный workflow **LMS assignments**.

Локальный запуск с настроенными переменными окружения:

```sh
pip install -r requirements.txt -r lms-requirements.txt
python run_checks.py
```

Это запуск с записью в настоящий календарь и отправкой сообщений.
Для проверки кода без обновления календаря используйте:

```sh
python -m unittest discover -v
```

## Проверка без изменения календаря и Telegram

```sh
python run_checks.py --preview
```

Этот режим запускает тесты и читает настоящее расписание и календарь,
но ничего не записывает и не отправляет. В журнале остаются только общие
счётчики событий, обновлений и ожидающих уведомлений.
В workflow **Schedule sync** тот же режим включается параметром **audit**.

## Как сравниваются изменения

Название предмета — часть строки до разделителя `·`.
Преподаватель, примечание и номер пары сравниваются по отдельным полям описания;
аудитория — по полю места, дата и время — как моменты времени с часовым поясом.
Повтор этих данных после `·` не считается отдельным изменением названия.
Поток не включается в события и сообщения.

При сравнении текста игнорируются регистр, пунктуация и пробелы оформления,
но сохраняются порядок слов и границы чисел: «Гр.1,2» отличается от «Гр.12».
В уведомление включаются только изменившиеся поля. Их старые и новые значения
показываются целиком, чтобы не обрывать имена, номера групп и условия занятия.

## Исключённые занятия

Элективные занятия, дисциплины и курсы по физической культуре и спорту
не добавляются в календарь. Ранее импортированные события с этим предметом
удаляются, включая прошедшие, без Telegram-уведомлений. Это явное исключение
действует независимо от `ENABLE_DELETIONS`. Другие занятия физикой и вручную
созданные события фильтр не удаляет.

## Расписание на дату в Telegram

`daily_schedule_bot.py` принимает сообщения в настроенном личном чате:
`18 октября`, `14 ноября`, а также дату с годом — `14 ноября 2027`.
Без года выбирается ближайшее наступление даты, включая сегодня.
Бот читает свежее расписание СКОЛКОВО, не изменяя Google Calendar.

На каждое занятие отправляется одно сообщение, по времени начала:

```text
1 пара · 14 ноября
10:00–11:30
Финансы
Преподаватель: Иван Петров
Примечание: Контрольная. Взять калькулятор.
Аудитория: 201
```

Четыре занятия — четыре сообщения, без дополнительного заголовка.
Если занятий нет, придёт одно сообщение «На 14 ноября занятий нет».
Физкультура из списка исключений и поток не показываются.
Тесты, контрольные, группа и формат занятия сохраняются из названия и примечания;
бот не определяет их по цвету и не придумывает недостающие данные.
Если номер пары отсутствует в источнике, это будет указано явно.
Очень длинное описание сокращается до лимита Telegram, сохраняя одно сообщение на занятие.

### Постоянный запуск

Для ответов сразу после сообщения нужен постоянно работающий процесс.
Обычный запуск синхронизации дважды в день входящие сообщения не обрабатывает.

На сервере создайте `.env` с четырьмя существующими настройками:
`TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`, `SKOLKOVO_EMAIL`, `SKOLKOVO_PASSWORD`.
Не добавляйте этот файл в Git. Для запуска подготовлены Dockerfile и Compose:

```sh
docker compose -f compose.bot.yml up -d --build
```

Или с установленными зависимостями:

```sh
pip install -r requirements.txt
python daily_schedule_bot.py
```

Команды `/start` и `/help` показывают подсказку по датам.
Бот отвечает только в указанном личном чате. Другие чаты и группы игнорируются.
Он использует Telegram long polling; второй получатель обновлений для того же
токена одновременно работать не должен. Если у бота настроен webhook,
процесс остановится с сообщением об этом, ничего не меняя в настройках Telegram.

### Состояние отправки

Состояние хранится в `work/telegram-bot.sqlite3` или по пути `--state`.
Там находятся ожидающие ответы и прогресс их отправки. Файл приватный,
исключён из Git и Docker-образа; в Compose используется постоянный том.
Не удаляйте его при перезапуске. После частичной отправки бот продолжит
с оставшихся пар, а обработанные запросы повторно не отправит.
Как и у любой отправки через сеть, при обрыве связи между принятием сообщения
Telegram и сохранением подтверждения возможен повтор последнего сообщения.

`python daily_schedule_bot.py --once` обрабатывает накопившиеся сообщения один раз
и завершается. Для регулярных запусков сохраняйте тот же файл состояния.
Содержимое переписки и расписание бот в журналы не выводит.
