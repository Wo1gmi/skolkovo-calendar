# skolkovo-calendar

Синхронизация расписания СКОЛКОВО с Google Calendar и уведомления об изменениях в Telegram.

## Проверить и обновить расписание

В GitHub откройте **Actions → Test and update schedule → Run workflow**.
Выберите ветку с изменениями и запустите проверку.
После первого слияния workflow в `main` он появится в списке Actions.

Запуск выполняет все тесты проекта, затем записывает актуальное расписание в календарь.
При изменениях отправляет обычные уведомления, а в конце — сообщение с датой,
временем и количеством добавленных, обновлённых и удалённых событий.
Даже если изменений нет, итоговое сообщение придёт.
Если тесты не проходят, календарь не обновляется.
При ошибке синхронизации уже выполненные изменения могут остаться в календаре;
запуск отмечается как неуспешный.

Для запуска используются те же секреты GitHub, что и для обычной синхронизации:
`SKOLKOVO_EMAIL`, `SKOLKOVO_PASSWORD`, `GOOGLE_SERVICE_ACCOUNT_JSON`,
`GOOGLE_CALENDAR_ID`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`.
Удаление отменённых занятий зависит от настройки `ENABLE_DELETIONS`.
Ручные цвета не сбрасываются. Задания LMS этот запуск не синхронизирует;
для них остаётся отдельный workflow **LMS assignments**.

Локальный запуск с настроенными переменными окружения:

```sh
pip install -r requirements.txt -r lms-requirements.txt
python run_checks.py
```

Это запуск с записью в настоящий календарь и отправкой сообщений.
Для проверки кода без обновления календаря используйте:

```sh
python -m unittest discover -v
```

## Проверка без изменения календаря и Telegram

```sh
python run_checks.py --preview
```

Этот режим запускает тесты и читает настоящее расписание и календарь,
но ничего не записывает и не отправляет. В журнале остаются только общие
счётчики событий, обновлений и ожидающих уведомлений.
В workflow **Schedule sync** тот же режим включается параметром **audit**.

## Как сравниваются изменения

Название предмета — часть строки до разделителя `·`.
Преподаватель, примечание и номер пары сравниваются по отдельным полям описания;
аудитория — по полю места, дата и время — как моменты времени с часовым поясом.
Повтор этих данных после `·` не считается отдельным изменением названия.
Поток не включается в события и сообщения.

При сравнении текста игнорируются регистр, пунктуация и пробелы оформления,
но сохраняются порядок слов и границы чисел: «Гр.1,2» отличается от «Гр.12».
В уведомлении сначала показывается актуальная карточка пары: дата, время, номер,
предмет, преподаватель, примечание и аудитория. Поток не включается. Ниже, в блоке
«Изменилось», перечисляются только изменившиеся поля с полными старыми и новыми
значениями. Повторяющиеся приписки и оформление сами по себе сообщения не вызывают.

## Исключённые занятия

Элективные занятия, дисциплины и курсы по физической культуре и спорту
не добавляются в календарь. Ранее импортированные события с этим предметом
удаляются, включая прошедшие, без Telegram-уведомлений. Это явное исключение
действует независимо от `ENABLE_DELETIONS`. Другие занятия физикой и вручную
созданные события фильтр не удаляет.

## Повторно актуализировать пару и прислать её карточку

Обычная синхронизация отправляет карточки только при реальных изменениях.
Для явного повторного обновления одной пары укажите в workflow **Test and update schedule**
параметры `refresh_day`, `refresh_subject` и `refresh_time` (московское время).
После тестов будет обновлено только одно точно совпавшее событие и отправлена
его актуальная карточка, даже если данные уже совпадают. Перед отправкой результат
повторно читается из Google Calendar. При отсутствии или нескольких совпадениях
операция останавливается. Ручной цвет сохраняется, остальные занятия не меняются.

```sh
python refresh_lesson.py --date 2026-12-04 --subject 'Искусственный интеллект в бизнесе' --time 10:00
```
